## Challenges & Growth Areas 🔧

### 1. **Aspire 13.0 Breaking Changes (Story 1.2)**
**Severity:** HIGH - Major blocker for Day 1-2

**Issues Encountered:**
- Wrong SDK declaration (`Microsoft.NET.Sdk` → `Aspire.AppHost.Sdk/13.1.0`)
- Missing `AddViteApp` method (required `Aspire.Hosting.JavaScript` package)
- Endpoint name conflicts (HTTPS/HTTP auto-configuration)
- `ASPIRE_ALLOW_UNSECURED_TRANSPORT` environment variable required
- OTLP endpoint configuration errors (wrong variable names)
- Missing Resource Service endpoint URL

**Resolution:** Complete troubleshooting guide created in Story 1.2 documentation

**Team Quote:**
> "Aspire 13.0 literally dropped during our epic. The migration docs were incomplete." - Charlie (Senior Dev)

**Lesson:** When adopting cutting-edge tech, allocate time for undocumented breaking changes

### 2. **Recurring Environment Variable Validation Gaps**
**Severity:** MEDIUM - Caught by code review across 3 stories

**Pattern:** Stories 1.4, 1.6, 1.7 all missing null checks for required env vars

**Resolution:** Added validation with helpful error messages, pattern documented for reuse

**Team Quote:**
> "We kept forgetting to validate environment variables. Code review caught it." - Bob (Scrum Master)

**Lesson:** Create reusable patterns for common requirements (env validation, error handling)

### 3. **MSAL Component Testing Complexity (Story 1.4)**
**Severity:** LOW - Testing strategy adjusted

**Issue:** MSAL.js requires extensive mocking (MsalProvider, Logger API with clone method)

**Decision:** Pivoted to integration tests + manual testing instead of complex mocks

**Team Quote:**
> "That MSAL Logger mock was ridiculous. It wanted a `clone()` method – who mocks that?" - Charlie (Senior Dev)

**Lesson:** Pragmatic testing - choose approaches with best coverage/effort ratio

### 4. **Story Status Inconsistencies**
**Severity:** LOW - Process improvement needed

**Issue:** Stories 1.3, 1.5 show "review" in story files but "done" in sprint-status.yaml

**Team Quote:**
> "That's a process issue. We need to sync story files with sprint-status.yaml at completion." - Alice (Product Owner)

**Lesson:** Single source of truth for story status prevents confusion
